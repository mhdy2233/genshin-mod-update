# 实例：黑红流浪者攻击特效修改与修复

这是 **2026-11-09** 的已留证案例：PC 原神 `OSRELWin7.0.0`、Direct3D 11、GIMI 8.9.2、XXMI DLL 1.2.3。用户报告皮肤正常，5.5 时的暗红攻击效果在当前版本不生效。以下标识仅描述这个案例；新角色、新客户端或新作用范围需要重新定位。

## 目标与来源

原 ZIP 的 27 个文件与本地原目录逐字节相同，没有漏解；包内没有独立攻击程序或历史暗红色值。五个旧反光/描边 ShaderOverride 的存在不足以说明攻击归属。公开的旧特效包证明过“角色激活 + Shader 输出改色”的实现方式，但未作为 7.0 补丁安装。

因此本次实现的是按用户目标制作的深红候选，并修复其兼容性；没有宣称重新找回 5.5 当年的逐像素效果。Head/Body/Hat 本来有 NormalMap 且皮肤正常，没有套用其他角色的 NNFix 或骨骼迁移。

## 从采集到修改

首次全场景纹理/常量抓取产生数千文件并长时间停顿，两次日志分别在 draw 224、194 附近截断。去重不能避免 GPU 读回，未重复该方案。恢复配置后改为 `analyse_options=log`，得到约 1.7 MB 的完整文字帧；再单独导出缺失程序代码。重击/E 阶段另外取得四份完整小日志，没有资源导出。

完整帧证明同一 PS 可用于不同纹理组合，普攻与重击/E 不能靠文件名或代码相似度统一替换。实现分为：

1. 主 `Wanderer.ini` 仅给实际 Head/Body/Hat 绘制各加一行本套皮肤激活标记，保留正常材质和 CRLF。
2. 独立 `WandererFX.ini` 根据当前程序的精确声明、内部指令与输出片段修改 RGB；运行时再检查皮肤激活、全局开关和实际纹理组合。
3. 本次深红输出用原 RGB 最大分量乘 `(0.65, 0.008, 0.028)`，保留原 alpha 和非目标路径。临时参数绘制后清除，皮肤激活帧末重置。
4. 首轮六组规则针对普攻八个 draw。重击/E 补充时保留它们的 RGB 程序，只给两处判断追加新组合，并新增 15 个实际取证的程序变体。一项四帧共用但用途未确定的程序未加入。

原主 INI 的模型、材质、hash 与缓冲布局未重写，26 个原资产文件保持相同，新增特效 INI 和说明。此案例不能推导出“所有特效修改都不需要改贴图”。

## 五个候选版本说明了什么

| 版本 | 观察到的问题/结果 | 修正及依据 |
| --- | --- | --- |
| 1 | 原生 PCRE2 匹配通过，F10 仍报错 | `.Pattern0/.Pattern1` 不受该加载器支持，整组禁用；测试遗漏了 INI 加载层 |
| 2 | 合并成一个 pattern 后仍报错 | 正文的行首 `[\s\S]*?)` 被 INI 首个 `]` 规则当新段；正则合法不等于 INI 合法 |
| 3 | 用户确认普通风刃生效，重击/E 未变 | 避开行首方括号后六组实际命中；后续需要补动作的程序/绑定，不能继续改同一个语法问题 |
| 4 | 新增 15 组后用户确认“特效可以看到了”，但 F10 有提示 | 日志 19/21 组实际匹配，没有组装错误；提示来自同一个 `cb888b02` 重复标记 |
| 5 | 后续两次重载的该冲突消失 | 复用 Tracking 库标记，21 种改色程序与原纹理条件不变 |

第 5 版的修改可用四条事实复核：

- GIMI 已有 `[TextureOverride Water Drop]`，`hash = cb888b02`，`filter_index = 111.69`。
- 第 4 版又为同一 hash 声明本地标记 `705533`；只检查数值标记空闲会漏掉这个冲突。
- 删除本地重复段，将原 `ps-t0 == 705533 && ps-t1 == 705534 && ps-t2 == 705535` 中第一项改为共享 `111.69`，其余条件不动。
- 没有用 `match_priority` 压掉提示或改写 Tracking 库。候选对该共享标记的依赖写入了说明。

## 验证边界与交付

静态检查在 243 个已导出 PS 中确认 21 组各自只匹配目标代码，普通帧仍选择八个 draw，新增四帧分别选择 13/0/11/7；alpha 写入及未涉代码可反向恢复，41 个本地 hash 无活动配置冲突，另一个标记复用共享库。

后续两次实际第 5 版重载耗时 0.649 / 0.650 秒。两段读取到 21 组、41 个本地标记和共享 `111.69`，无新的解析/组装错误或重复纹理警告；最后一段 16 组实际匹配。画面结论引用用户对普通风刃及扩展特效的反馈，没有将每层效果或跨角色隔离标为全部通过。

接手续做时发现实际 INI 已是第 5 版，但 ZIP/交付回执仍是第 4 版。日志已有修复后的成功重载，故先归档并同步包、说明、回执，再恢复临时日志设置，没有重新应用补丁或要求重复 F10/F8。

## 在新修改中复用

复用的是“动作 → 程序/绑定 → 受限条件 → 最小输出修改 → 实际加载与画面”的链路。若用户以后要求另一个颜色，先核实当前有效候选与其代码，再修改已定位的颜色运算并检查未涉通道；若要求另一种动作，先补该动作证据。不要将案例的 21 个 hash、`x197/t120`、过滤编号或深红系数作为通用模板。

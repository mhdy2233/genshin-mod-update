# Android：修改、版本升级与跨平台适配

只有当前任务涉及安卓资源/模块，才读取此分支。**PC MOD升级、PC→安卓移植、安卓客户端版本升级是三件事。**目标沿用同一游戏版本也可能存在地区、资源修订、图形后端或native二进制差异。

明确要求PC→安卓时，先读[转换流程与可执行入口](pc-to-android.md)。本页继续处理目标布局和运行时适配；校准预设的转换成功不代表任意PC包通用支持。

同版本定向修改也按下面的对象链定位。用户只改配色、部件、透明或特效时，复用已核实的当前布局与接口，实际修改所需资源/参数；不为了使用迁移流程而更换客户端或重新扫描全量资源。

## 建立对象链，而不是先猜偏移

固定目标APK/split、游戏版本/修订、资源版本清单与目标native库摘要。由角色资产或已核对资源索引定位：

`角色预制体 → Renderer → Mesh + 材质槽 → Material → Shader/Texture → 所在CAB/BLK`

逐层保存PathID/FileID、类型/布局hash、偏移与大小、依赖关系。复用已知索引和目标块，按需扩大扫描；名字相近、同名Body或同样材质不能证明是正在使用的角色实例。目标客户端的数据格式才是当前真值，不能把上一版路径/地址作为常量。

## 差异表与修改

| 变化层 | 如何找差异 | 修改与不变项 |
| --- | --- | --- |
| BLK/CAB封装 | 段头、压缩/编码、节点路径、对象表、alignment和类型hash | 从新版本有效样本先做不修改的逐字节往返，再构造独立输出；回读对象边界与依赖 |
| Mesh布局 | channels/stream/stride/format、index格式、submesh、bindposes、bone hashes和边界 | 按新布局写原模型数据；索引/骨骼域要有证据。不能凭顶点数相同就认为语义相同 |
| PC与安卓几何 | 官方同角色的逐顶点位置/法线/切线/UV/颜色/权重/骨骼索引 | 只有实际一致才直接复用；否则证明坐标变换或骨骼映射。不要默认轴翻转或重新绑权 |
| 贴图 | 当前目标尺寸、GPU格式、mip数、通道含义和sRGB | 只在平台或目标格式需要时重采样/编码，并说明有损变化；不要把所有版本写死1024或某个ASTC块大小 |
| Material/Shader | 原始序列化布局、纹理环境字段、属性、关键字、pass标签、混合/深度/剔除 | 比较实际执行的程序与绑定，不靠Alpha/Outline等名称判断功能；保持diffuse-alpha等原用途 |
| native接口 | 类型描述、函数引用/调用约定、结构访问及机器码指纹 | 重新核对目标库；用真实RuntimeType和正确的返回容器ABI。旧地址匹配失败就停止调用，不能只换一组偏移碰运气 |
| 运行时对象 | 新旧renderer/material ID、owner/父链、数组槽数、启用状态 | 在正确引擎线程按对象归属操作，只写独占材质；等待新实例就绪后补绑，停用时恢复且不再次套回 |

## 同版本外观与特效修改

按 [定向修改](mod-editing.md) 明确目标区域和动作。改颜色先确认纹理通道/Shader 实际读取的属性，改部件先确认 renderer/submesh 和保存状态，改攻击特效则定位其独立预制体、粒子/网格、材质及程序；角色 Body 的材质不自动拥有技能特效。

PC 的角色激活与程序/输入组合限制可以作为取证思路，但 PC ShaderRegex、DXBC、`filter_index` 和 `ps-tN` 不能直接写入安卓链路。使用本客户端的对象归属、独立材质/资源及当前程序结构实现同一目标；需要改 alpha/混合或新增采样时继续检查下面的 pass 与绑定元数据。

设计需要时可编辑贴图、几何和程序，原件另存；无关的法线/遮罩/alpha、动画权重及原装恢复入口保持可追溯。UI 的“已应用”必须对应实际材质槽/对象更新；涉及传送重建或停用恢复时，只测试此次改变的生命周期。

## Shader迁移的具体易错点

1. 一个Shader可有多个同名/不同关键字pass，某些子程序为空或指向去重代码。沿program hash/依赖找到真实程序，保留原输入/输出接口、资源绑定和平台变体。
2. 若修改SPIR-V并保留引擎的绑定表，不要用友好名称程序集重新组装导致ID重排。直接按原字流打补丁、新ID大于旧bound，并验证可还原；另一种可行路线是完整重建所有绑定元数据，但工作量更大。
3. 新增采样器不只是加一个OpVariable：还需要正确的descriptor set/binding、Shader属性、pass名称表、实际GPU参数尾表、Material纹理项，以及顶点/片元UV location和类型一致。每一层都从最终封装回读验证。
4. 编码器版本按目标引擎核定。历史案例使用20160831旧SMOL-V，不能推广为所有新版都必须用它。用原样本编码回原字节、新代码独立解码，并在游戏中验证加载与对象身份。
5. 延迟渲染pass输出多个中间缓冲，不能改个标签就当作透明前向最终颜色；要确定哪个通道是真颜色、深度/剔除/排序怎么工作。全透明区域的深度或描边不能留下不透明外壳。
6. `spirv-val`、主机离屏测试、游戏Shader加载、材质绑定、最终像素效果是不同验证层。保留各层结论，不能用前一层替代后一层。

## 子网格增加必须检查所有依赖

从2槽改为3/4/5槽之类的适配，不仅改变转换器。还要检查：材质分配、Body识别、翼装归属、源资源扫描、缓存模式、JNI参数、原装移除、重建补绑及日志。

新转换用新mode显式描述绘制结构；旧缓存继续按旧槽数应用或明确迁移。避免“皮肤已经换了，后面的翼装检查失败，最终选择没保存”的半应用状态。最终结果与状态提交必须覆盖整个应用链。

读取`status=applied`时核对时序：它可能是首次应用的旧快照。传送后应看到**新renderer ID**、所属角色/材质和纹理读回；停用后新实例保持原装，不能只看旧对象的恢复记录。

## 7.0 / Luna管理器已证实的运行时坑

- **-218材质来源。**实际名称可能是`原名 (Instance) #0`，还可能重复实例后缀。仅材质匹配接受已确认的实例/数字语法，继续核对角色、槽位和基名；共享来源可以只读，不能据source owner不等于当前renderer就拒绝。
- **复制可能返回原对象。**本版`0x58bb32c`在源owner等于renderer时直接返回源指针。0.4.1修复通过null源创建独占材质，再复制属性和名称，读回owner、shader、参数数据独立性，停用恢复原槽。该地址和语义只针对已核对的v12引擎，不直接推广到新版。
- **-204首骨骼不是根骨骼。**当前Mesh+0x80为骨骼名称哈希数组指针、+0x90为其数量，+0xc0为根哈希。流浪者Body首哈希4147084987、根哈希2215216970，根在第100槽；刻晴两者相同掩盖了旧错读。0.4.3修复运行时读取，包的`firstBoneHash`和骨骼顺序保持原样。新版本按具名序列化字段和实际指令重新确认布局，不能套用偏移。
- **重启后-220与资源生命周期。**开始页没有角色时应返回等待；本次实际失败发生在角色出现后，预加载贴图的地址仍非空，但实例ID已失效或被复用。C++保存指针不等于Unity保留对象。0.5.2在绑定前检查本条规则引用的Mesh、模板材质和贴图身份；失效时保留待绑定renderer，在既有Unity主线程tick重新取资源，再完成绑定。存活bundle可重新取对象，bundle也失效才重开文件，同一路径替换缓存项；不要在资源解析/Awake回调中递归加载。错误按renderer记录，等待不算恢复，完整读回成功才计入绑定数量。诊断应区分贴图失效与setter/槽位读回失败，不能对所有-220盲目重载。
- **切角色先错图再恢复。**游戏会恢复原装Mesh，而MOD贴图仍在，等一秒定时维护会留下短暂UV错配。0.5.3在既有SetMesh入口即时保持已就绪的替换Mesh；只对身份、归属和骨骼已验证的renderer生效，停用或资源未就绪时交还原路径。
- **切角色约两秒后紫/绿覆盖。**默认角色可正常，后来切出的角色会在临时溶解Shader下首次复制材质；游戏切回普通Shader，副本却仍保留临时Shader及`_DissolveValue=1`、`_EnableCharacterDissolve=1`和颜色。0.5.4同步`SHADER_LERP_CHAR_DISSOLVE`开/关仍未完全修复，0.5.5由源Shader切换后刷新同一独占副本的完整参数，再重套MOD属性解决。分别检查Shader身份、参数表、关键字和像素结果；只镜像数值或硬编码清零不够。仅对沿用角色源Shader的材质做此同步，FX独立模板不继承原配色。
- **FX存在但没有绑定。**本次对象池中640个流浪者FX renderer有518条规则可匹配，最初加载/Awake入口却未再触发。0.5.4在激活时按类型、特效根名、相对路径和材质名绑定；归属保存renderer到特效根的内部父链，允许整个根移动到池或场景。不能把根正常换父当作丢失归属；子节点脱离或ID复用仍拒绝。

0.5.5的重启进场与角色切换画面已由用户确认，流浪者皮肤与当次所测特效在0.5.4也获确认。全部选项、动作和长时联机未做全量覆盖；0.5.5有6条过渡期颜色读回失败，随后出现恢复与完整Shader更新，不能写成全程零告警。大量`owner_changed`或日志额度耗尽都需结合实际时序解读。证据与复现入口见[转换参考的故障表](pc-to-android.md#故障与验收记录)。

## 验证范围与权限

原游戏块、PC输入和已接受Shader缓存保持可追溯；生成独立CAB/BLK身份与缓存，保存原装资源入口。只在授权范围更新测试包/资源；本skill不授权启动游戏、注入触摸或发布。

按当前会话划分设备操作：用户已授权ADB退出/重启时直接沿用，不再重复要求手动退出；这不自动授权点击、滑动或按键。用户负责前台操作时，给出最短动作，收集真实新进程的日志和截图。变更涉及生命周期就验证自动补绑和停用；不重复已经通过且未改变的支路。用户暂缓的细阴影/描边对照继续保留。

最终说明相同与不同：作者几何/权重/图案是否保留，贴图是否缩小重压缩，材质是否重写，哪些原PC效果未覆盖。版本升级成功不代表PC与安卓逐像素等效，也不意味着任意角色已通用支持。

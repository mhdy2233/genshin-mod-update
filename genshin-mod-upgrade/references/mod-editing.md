# 同版本 MOD 修复与定向修改

用于“改成这个颜色”“隐藏某部件”“修改默认开关”“调整透明/双面”等要求。客户端可以保持同一版本。修复是恢复应有行为，定向修改是实现新目标；两者都需要定位实际控制点，但新配色不需要伪造旧版对应值。

## 将目标对应到资源

先从当前已工作的副本开始，核对用户指的是哪套皮肤、哪个部件/动作，以及开关是否已有保存值。目标已清楚就执行；只有缺少会改变实现的范围、参考或参数时才问。把原件、当前修改版和输出候选分别标识，已有改装不回退成“更原始”的文件。

| 用户目标 | 先找到什么 | 最小修改位置与检查 |
| --- | --- | --- |
| 衣服/局部配色、替换图案 | draw 实际采样的 Diffuse/颜色通道、UV 区域、sRGB 与 alpha 用途 | 若现有颜色参数足够就改参数；否则编辑对应纹理区域，保留无关通道、尺寸/mip/目标格式并回读编码结果 |
| 修复白色、黄绿、异常高光 | NormalMap 是否存在、真实槽位、LightMap/MetalMap/ShadowRamp 与当前库入口 | 先修绑定或库调用；按 [PC 材质参考](pc-migration.md) 判定，不能用调色掩盖错误输入 |
| 披风或帽子显示身体等其它部件的图案 | 错误图像能否对应已有图集、真实材质槽、对象名称与性能属性/关键词 | 图像已存在时先修绑定、对象身份或状态；iOS 的独立 Hat 与贴图命名实例见 [iOS 披风案例](ios-wanderer-cape-fx-case.md) |
| 部件显示、默认选项、切换档位 | INI 的有序条件、cycle 列表、部件 draw 范围、持久化变量/用户配置 | 修改已有分支或默认值；保留实际多档列表，不能把 0/1/2/3 简化成布尔值，也要排除旧保存值覆盖新默认值 |
| 几何形状、部件大小/位置 | 目标顶点域、Position/Normal/Tangent、IB、蒙皮与边界 | 在独立数据中改目标顶点，按变形需要更新法线/切线/边界；数量或拓扑变化时同步检查相关流、draw、索引、骨骼和容量 |
| 透明、双面、描边 | 实际 pass、遮罩通道、混合/深度/剔除，以及已有 TexFx 或其他扩展 | 优先使用当前版本支持的机制，只处理目标表面；验证背面、透明深度/排序及描边是否一起符合目标 |
| 攻击、技能、拖尾或光效改色 | 效果出现时的 Shader、纹理组合、输出/常量及开关条件 | PC 读 [特效参考](pc-effects.md)，iOS 读 [原生特效](ios-mods.md)；皮肤贴图通常不能代表全部攻击特效 |

移动端的同类需求先建立实际对象链，分别按 [安卓参考](android-migration.md) 或 [iOS 参考](ios-mods.md) 修改材质/独立资源。PC INI 中的槽位、Shader 文件或 hash 不能直接当移动端接口；安卓 SPIR-V 与 iOS Metal 也分别处理。

## 配色与材质

纹理文件名不能说明所有通道的用途。先区分颜色、法线、光照分类、金属、遮罩及 alpha 数据；Diffuse 的 alpha 也可能存材质标记。只改 RGB 的任务不要顺带覆盖这些通道。颜色值记录为 sRGB、线性值或已验证的 Shader 输出系数，避免把 UI 颜色直接当所有阶段的线性常量。

对同一资源有多个 mip、LOD 或不同动作绑定时，确认需要修改哪一层。只在目标平台/格式需要时重采样和压缩；编辑后的 DDS/PNG/ASTC 需要回读尺寸、格式和实际像素。共享贴图或材质可影响别的部件，先限定替换 draw 或创建独立资源，不仅凭资源名字判断归属。

## 部件、选项与几何

修改部件开关时，沿条件追到具体 `drawindexed` 或 renderer/material 槽。整段跳过可能同时隐藏皮肤、阴影、风之翼或其他共用对象；按用户要求选择作用范围。使用原有选项解析和保存机制，分别确认运行中选择、下一次加载及关闭恢复所对应的状态。

几何改动可以是需求本身，不强行限制为只改 INI。只有目标形变涉及的内容才重新导出；正常权重不自动归一化、不借别的衣服 Blend 凑数据。改变顶点数或拓扑时按 [PC 几何检查](pc-migration.md) 核对整条资源链；只改默认开关不运行骨骼迁移。

## 透明、双面与 TexFx

核对本套 MOD 真正执行的 TexFx 命令和已安装库版本，再解释遮罩。历史 TexFx 1.0661 案例中，t69 红通道承担透明控制：0 走不透明路径，255 丢弃，中间值对应 `1 - R/255` 的合成 alpha；这不是所有纹理 alpha 的通用解释。t70 描边及背面额外绘制是另外的链路。

透明度、双面剔除、描边、深度和排序分别验证。整材质设置 `Cull Off` 或 alpha blend 不能自动复现 TexFx 的分层绘制；先确认当前 Shader/pass 支持什么，必要时拆分目标表面。Android 的新增 pass/采样器还要同步绑定元数据，不能只改同名属性。

## 实施和交付

按用户目标实际生成候选，列清改过的配置和资产。如果需要取证才能确定控制点，先做可完成的盘点和准备，再给出最短的游戏操作；用户负责前台时不代按热键或触摸。

按变更选验证：局部改色检查目标区域与保留通道；开关检查对应档位/恢复；共享材质或全局规则检查受影响的其他绘制；透明/几何检查相关视角或动作。执行过的结果与未覆盖范围分开写入 [修改记录](migration-record.md)。正常的文件加载不能代替用户要的实际外观。
